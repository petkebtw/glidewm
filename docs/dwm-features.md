## dwm.c / config.h features

- Floating bar: `vertpad`, `sidepad`, `barpad`; `sp/vp/gp(m)` return 0 when `barflush(m)` (monocle-like or any tiling layout with exactly one window). `arrangemon` updates bar position first. Gaps `gappx`: `Mod+-`, `Mod+=`, `Mod+Shift+=` (reset 10).
- Tags drawn as dots/pill with cairo; `tagw(sel)` slot width, `TAGX0` left pad; `buttonpress` and `drawbar` must stay in sync. `tagf[]` eases dot to pill; `animstep()` runs from an 8 ms `select` poll while `baranim` is set. `blendpx` assumes 24-bit TrueColor.
- Right cluster (systray, volume icon, clock, avatar) is on every bar. Real tray pinned to monitor 1 (`systraypinning = 1`); other bars mirror it (`drawtraymirror`, `traymirrorclick` via XTest, `-lXtst`). `rlayout()` is the single source for click mapping and drawing. `stext` format: `"<m|0-3>\x01date  time"` from `dwm-status`. Tray window class `dwmtray`. cairo-xlib needs the XShm bounds check in `run()`.
- Colours: `loadxrdb()` reads `dwm.{norm,sel}{bg,fg,border}color`; `propertynotify` reloads on `RESOURCE_MANAGER`; `Mod+F5` also.
- Borders only on the focused client (unfocused get `border_width 0` and +2*bw size); outline crossfade (`bm`/`bt`).
- Window animation: per-client displayed/start/target geometry, `easeg` bezier .22,1,.36,1, `GEODUR` 0.22 s. New windows are NOT animated (a shell in a new Konsole must see its final size). `noanim` during mouse drags and canvas panning. While a game runs (`detectgame()`: WM_CLASS `steam_app_*` or `SteamGameId/SteamAppId` in the process env) only the position eases. Workspace switch slides via `view()` `swipedir`, `park`.
- Layouts: tile, `bento` [B], `dock` [D], `mosaic` [#]; `Mod+space` cycles (`cyclelayout`), `Mod+Ctrl+space` = tile, `Mod+Shift+space` floats one window. Bar label from `layoutnames[]`. `attach()` is stock (new window = master).
- Keys: `Mod+Shift+j/k` movestack; `Alt+arrows` snap half/quarter, `Alt+Shift+arrows` move 48 px, `Alt+Ctrl+arrows` resize; `Mod+Shift+g` canvas mode; `Mod+Shift+l` lock; `Mod+Shift+r` recorder; `Mod+o` settings, `Mod+Shift+o` tools, `Mod+s` search, `Mod+v` clipboard, `Mod+Shift+t` theme switcher, `Mod+Shift+m` media, `Mod+z` map, `Print`/`Mod+Shift+s` shot.
- Runtime binds: `~/.config/rice/binds.conf` REPLACES the compiled `keys[]` when it exists (edits to `keys[]` do nothing until the file is deleted or reset in Settings > Shortcuts). `dwm --dump-binds` prints the compiled table. Bindable actions are in `actions[]`.
- Canvas mode: layout is `canvaslayout` (no arrange). Pan by dragging the background or `Mod+Shift`+drag (`canvaspan`, clipped per monitor with XShape, `-lXext`). `Mod+scroll` = real canvas zoom (`canvaszoom`: moves and resizes every window about the pointer, 0.25-2.0x, instant); `Mod+Ctrl+0` resets. Bar capsule shows `canvas NN%`.
- IPC: `xprop -root -f _RICE_CMD 32c -set _RICE_CMD "N, ..."`. Two writes in a row swallow each other; leave about 40 ms between them. `1,X,Y` view first empty tag on monitor at X,Y; `2,px` gap; `3,px` gap above bar; `4,px` bar side gap; `5,0` reload binds; `6,[X,Y]` dump monitor to `_RICE_MAP[_mx_my]`; `7,dx,dy[,X,Y]` pan eased; `8,dx,dy[,X,Y]` pan at once; `9,win` focus; `10,win,x,y` move. Tag hover (2026-11-25, backup `dwm.c.pre-tagpeek`): bars select PointerMotion/LeaveWindow, `taghover()` writes root `_RICE_HOVER` = {tag 1-9, tag middle x, bar bottom y, monitor, window ids} or {0} (cleared at start); the shell's TagPeek card reads it. `run()` steps the animation at least every 6 ms even while events keep coming.
- Rules: class `RiceAuth` (polkit) always floats. Fonts: JetBrains Mono Bold + Symbols Nerd Font.
- `syncptrmon()` selects the monitor under the pointer in `spawn()`, `manage()`, `keypress()`.
- Shell windows (Quickshell, 2026-11-24): `isshellwin()` windows are mapped unmanaged; `_NET_WM_STATE_BELOW` ones are lowered on every map; `scan()` skips them after a restart. `publishmons()` writes root property `_RICE_MONS` = per monitor {x, y, viewed mask, occupied mask} (hides widgets per monitor). `shellcheck()` + ShapeNotify gives the X focus to an ABOVE shell window with a visible bounding shape of at least 300x300 (an open menu: Esc and typing) and returns it to the client when the shape goes away (`shellfocus`; `focusin()` ignores it). `noslide()`: file `~/.config/rice/noslide` makes tag switches snap. A running dwm only changes after install plus a restart: compare `stat -L -c %i /proc/$(pgrep -x glidewm)/exe /usr/local/bin/glidewm` (the binary is `glidewm` since 2026-11-25; an old session runs `/usr/local/bin/dwm`). Details: `handoff-dss.md`.

## Shell ABOVE windows over floating clients (2026-11-24)
`shellabove[]` (filled in `shellcheck()`) = Quickshell windows with `_NET_WM_STATE_ABOVE` (dock, menus). `raiseshell()` at the end of `restack()` raises them again after a floating window is raised, except on a monitor whose selected visible client is fullscreen. Backup `dwm.c.pre-dockabove`. Needs `sudo make install` + restart. Untested live.

Name (2026-11-25): Makefile builds and installs `glidewm` (`/usr/local/bin/glidewm`, `glidewm.1`); `-v` prints `glidewm-VERSION`, `_NET_WM_NAME` of the check window is "glidewm". Kept as dwm on purpose: X resources `dwm.*` (themes.py writes them), the bar window class `dwm` (picom rules, rice.py), `dwm.c` file name. Backups `Makefile.pre-glidewm`, `dwm.c.pre-glidewmname`.

Restart keeps windows (preserveonrestart, by hand, 2026-11-25, backup `dwm.c.pre-preserve`): `quit {.i = 1}` (`Mod+Ctrl+Shift+q`) makes `cleanup()` write `_RICE_TAGS` = {tags, monitor num} on every client and root `_RICE_VIEW` = {selected monitor num, view of monitor 0, 1, ...}. `manage()` reads the window's pair (puts it back on its monitor unless it is transient), `main()` restores every monitor's view and the selected monitor. A one-value `_RICE_VIEW` from an older build still works. Before: the key restart put every window on the pointer's monitor (reproduced in Xvfb with a fake 2-monitor Xinerama, `LD_PRELOAD` shim `fakexi2.so` in the scratchpad: 1280x1440 root, bottom screen 0, top screen 1, like DP-4/HDMI-0).
