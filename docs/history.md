# dwm rice (Gentoo, X11)

Personal dwm 6.8 build on Gentoo. Upstream suckless source with the systray patch already applied, plus hand-edited rice features. The repo has uncommitted changes in `dwm.c`, `config.def.h`, `drw.c` and `drw.h`; `config.h`, `config.h.save` and the `*.o` files are untracked. Do not commit unless asked.

## Build and install

- Build: `make` in this directory. It compiles clean with `-Wall -pedantic`.
- Install: `sudo make install` copies to `/usr/local/bin/dwm`. Claude cannot run this (no TTY for the sudo prompt, even via `!`). Ask the user to run it in a real terminal, then restart dwm with `Mod+Shift+q`.
- `Mod` is Alt (`Mod1Mask`). Terminal is `konsole`, launcher is `rofi-launcher`.
- To test a build without installing, run it in Xvfb: `Xvfb :7 -screen 0 1280x720x24 &`, then `DISPLAY=:7 ./dwm`. Xvfb resets its X resources when the last client exits, so start dwm first, then `xrdb -merge`.
- Edit `dwm.c` by hand. Do not apply `.diff` patches: they conflict with the existing systray and rice edits. The `dwm-systray-*.diff` files are reference only.

## What was added to dwm.c / config.h

- Floating bar: `vertpad` (gap above bar) and `sidepad` (gap left and right), plus `barpad` (extra bar height). `sp(m)`, `vp(m)` and `gp(m)` return 0 when `barflush(m)` is true.
- `barflush(m)`: true for monocle with at least one window, or any tiling layout with exactly one tiled window. The bar and gaps then go flush to the screen edge. `arrangemon` calls `updatebarpos` and `resizebarwin` first, so this updates on every arrange.
- Gaps: `gappx` in tile and monocle. Keys: `Mod+-`, `Mod+=`, `Mod+Shift+=` (reset to 10).
- Tags drawn as dots (selected tag is a pill, occupied is a dot, empty is a small dot) via `XFillArc`. `tagw(sel)` gives each tag's width (a fixed 28px slot, so the pill can animate without shifting the layout), and `buttonpress` uses it for click mapping, so keep the two in sync.
- Tag animation: each `Monitor` has `tagf[]` (0 = dot, 1 = pill). `animstep()` eases it toward the target and redraws. `drawbar` sets `baranim` while any tag is unsettled, and `run()` then polls with an 8ms `select` timeout instead of blocking in `XNextEvent`. `blendpx` blends pixel colors and assumes a 24-bit TrueColor visual.
- Title is centered in the bar and uses `SchemeNorm`.
- Colors: `loadxrdb()` reads `dwm.{norm,sel}{bg,fg,border}color`. `propertynotify` reloads them live when the root `RESOURCE_MANAGER` property changes (any `xrdb -merge`). `Mod+F5` also reloads.
- Rules: the `RiceAuth` class (polkit dialog) always floats.
- Fonts: JetBrains Mono Bold with Symbols Nerd Font as fallback.

## Rice scripts (outside this repo)

All under `~/.local/bin` (shared Python in `~/.local/lib/rice/`), started from `~/.xprofile`:

- `theme-switch` + `lib/rice/themes.py`: carousel (`Mod+Shift+t`). There are no built-in color themes any more: every theme is a wallpaper, and its palette is extracted automatically (`palette()`, cached in memory and pre-extracted at download). Local wallpapers live in `~/Pictures/wallpapers` (about 25); downloaded ones in `~/Pictures/wallpapers/online/` and sort last. `apply()` writes `~/.cache/theme/{colors.json,colors.rasi,dwm.Xresources}`, runs `feh` and `xrdb -merge`. Arrow keys switch with live preview (120ms debounce), Enter keeps, Esc reverts. `--restore` runs at login.
- Online sync: `themes.sync(n)` pulls wallpapers from the source chosen in `~/.cache/rice/source` (`wallhaven` default, `minimal`, `both`; `s` in the picker cycles it). See "Session 2" below. Does nothing when offline. The picker fetches 10 on open and 10 more when you scroll near either end of the list, in a thread that splices new items in. `theme-switch --sync` and `--restore` also sync in the background. The online folder holds at most 150 files (`MAX_ONLINE`); older downloads are pruned, never the active wallpaper.
- `rice-shot` (`Print`, `Mod+Shift+s`): screenshot and annotation tool. It captures the whole X root so both monitors work. Repaints use dirty rects; full-window redraws lag badly (1920x2160 root).
- `rice-volume` (volume slider card), `rice-media` (MPRIS card, `Mod+Shift+m`, plus the media keys), `polkit-agent`, `clip-daemon` and `clip-pick` (`Mod+v`, now a rice Card with filter + image thumbnails; old rofi version `clip-pick.rofi`), `rofi-launcher` (`Mod+p`, now just `exec rice-search`; old rofi version `rofi-launcher.rofi`), `dwm-volume`, `dwm-status` (root-window status text), `audio-fix`. `rice-osd` (the old round volume dial) still exists but nothing launches it any more.
- `rice-volume`: a pill card with a rounded slider, a white knob and the percentage beside it. The drawn level eases toward the real level (16ms timer). Left-click on the bar status text opens it (`volmenu` in `config.h`, needs the rebuilt dwm); `dwm-volume` runs `rice-volume --osd` on every volume key. Click mode grabs input; Esc, right-click or a click outside closes it. `--osd` mode takes no grabs and closes 2 seconds after the last change. It centers at the top of the monitor under the pointer.
- `rice-volume` single instance: it takes `~/.cache/rice/volume.lock` with `flock` and writes `volume.pid` before importing GTK, because the GTK import is slow and a burst of wheel ticks otherwise starts several cards that each open and close. A second call sends `SIGUSR1` (refresh and restart the 2s timer) in `--osd` mode, or `SIGTERM` (toggle off) in click mode. A refresh that arrives while the card is closing makes it `execv` itself again after the close finishes. Keep `SIGUSR1` ignored at the very top of the script so an early signal cannot kill it.
- Rofi themes live in `~/.config/rofi/{launcher,wall,clip}.rasi` and import `~/.cache/theme/colors.rasi`.
- Popups share `~/.local/lib/rice/rice.py`. The `Card` class sets WM class `RiceCard`, which picom rules key on.
- Pop animation (2026-11-17, from the tiktok_shadoww.dev reference, container transform): menus open RIGHT UNDER THE BAR (`Card._dock_under_bar()`, `BAR_BOTTOM = 37`, `BAR_GAP = 8`; cards with `origin` keep their place; `Card.move()` forces the docked y even when a script moves the card after `show_all()`; `Panel` (rice-settings) sits at the right edge under the bar, class `RicePanel`, shape grows from its top-right). Mechanism (rice.py `Card._ghost`, `show_all`, `quit_anim`): the real card is mapped INVISIBLE (opacity 0, contents opacity 0) at its place; a `RiceGhost` popup (picom rule: blur + shadow, radius 26, no animation) is really resized each frame with one `move_resize` (width 0.2 to 1 in 0.26 s, height 0.08 to 1 in 0.38 s, top edge fixed) and draws only the blank rounded glass; at full size the real card becomes visible and `_fade_child` fades its contents in (170 ms). Close: contents fade (90 ms), a pre-mapped invisible ghost is revealed and shrinks (0.2 s), then `hide()` + quit. Why not picom animations for cards: a fresh X window holds leftover screen pixels until GTK paints it and, with picom's scale animation and corner rounding, a tiny copy of whatever is behind (the user's terminal text) showed up inside the growing shape; the real-resize ghost has no such artifact. picom rules `RiceCard`, `RicePanel` have no animations; `Rofi` (unused now) and `RiceAuth` (polkit, centre grow) still use picom animations. Backups `rice.conf.pre-*`, `rice.py.pre-*`. Use `quit_anim` instead of `Gtk.main_quit` to close a card. `rice-volume`, `rice-media` and `theme-switch` use it; `polkit-agent`, `clip-pick` (now a Card) and `rice-shot` do not (polkit fades contents via `rice.fade_child`).
- `rice-media` grabs the keyboard so Esc or `q` closes it. A card needs its own key grab to react to keys because it is an override-redirect popup.

## Environment gotchas

- Two monitors: DP-4 (primary, 1920x1080 at 0,1080) and HDMI-0 (above it, rotated inverted). Rofi and popups open on the monitor of the focused window or pointer.
- picom: `~/.config/picom/picom.conf` is root-owned and untouched. The real config is `~/.config/picom/rice.conf`, started from `~/.xprofile`. Everything per window class lives in a `rules = (...)` block there (picom 13; the legacy `*-exclude` options cause a warning popup, see Session 4). `blur-strength` is now written by the theme hook from the wallpaper (2-6, see Session 2). Konsole is no longer excluded from blur. Picom reloads its config on `SIGUSR1`; otherwise restart it.
- Audio: after a re-login, PipeWire can be left stale (sockets wiped, `wpctl` and `pactl` report "Could not connect"). `audio-fix` restarts the stack and reactivates the HyperX Cloud III profile. `dwm-volume` calls it automatically. The headset wheel sends `XF86Audio*` keys, which dwm binds.
- A hung PipeWire makes `wpctl` block forever instead of failing. Every `wpctl`, `pactl` and `audio-fix` call in the rice scripts must be wrapped in `timeout`, otherwise each key press piles up another stuck process. `dwm-volume` serializes with `flock` on `$XDG_RUNTIME_DIR/dwm-volume.lock` and starts `rice-volume` with `9>&-` so the child does not inherit the lock. `audio-fix` takes its own `flock` so two repairs never race (that once left two wireplumbers running). When testing, use `timeout 3 wpctl ...` yourself.
- `rice-media` drops a repeated media key within 0.4s, and next or prev only act on a player that is actually playing. Every key is logged to `~/.cache/rice/media.log` (check it when songs change on their own: a `Next` or `Prev` line means the key really arrived). The root cause of the SoundCloud freezing and random skips was not confirmed.
- `~/.local/bin/dwm-theme-select` does not exist; the theme key now runs `theme-switch`.

## Working rules for Claude here

- Never send `xdotool` key or mouse input to the live session unless the target window is confirmed up (for example `xdotool search --class RiceShot`). Keystrokes otherwise land in the user's terminal. Add `sleep` between synthetic mouse events, or they get dropped.
- `pkill -f` and `pgrep -f` match the calling shell's own command line and can kill it. Use `-x` with the exact process name, except for dwm and Xvfb tests: `pkill -x dwm` kills the user's live dwm. Start the test dwm with `./dwm & DP=$!` and `kill $DP`, and do the same for Xvfb.
- In an Xvfb test, set `DISPLAY=:7` for every command, including `xdotool`, so nothing reaches the live session.
- `pkexec` refuses to run when its parent shell has exited. Keep a live parent (`sh -c 'pkexec ...' &`).
- Screenshots of the full root include the user's other windows. Crop to the region under test with `maim -g WxH+X+Y`.
- Do not restart or replace dwm, PipeWire or picom without saying so first.

## Rice v2 additions (Nov 2026)

- dwm.c: animation core. Each `Client` has displayed (`ax..`), start (`fx..`) and target (`tx..`) geometry; `resizeclient` only sets the target, `animstep()` (8ms poll via `baranim`) eases it (ease-out quart, `ANIMDUR` 0.2s). `noanim` is set during mouse move/resize and canvas panning. New windows are NOT animated (see Session 4: a shell inside a new Konsole must see its final size); siblings still ease. Close cannot be animated in dwm (window already gone): picom `disappear` rule in `rice.conf` does it.
- Workspace switch: `view()` sets `swipedir`; `showhide()` slides old windows out and new ones in (`park`/`parked`). `tag()`/`toggleview()` do not swipe.
- Borders only on the focused window: unfocused clients get `border_width 0` and +2*bw size (`applygeom`, `hasb`), so layouts keep reserving `borderpx`.
- Bar: drawn with cairo (AA). Tag pill = two edges (`pl`, `pr`) with different ease speeds = stretch. Floating/flush bar animates (`flushf`): layouts use the target gaps (`sp/vp/gp`), the bar window uses animated `spa/vpa`. Right cluster = systray, volume icon (cairo), clock, avatar; `stext` format is `"<m|0-3>\x01date  time"` written by `dwm-status`. `rlayout()` is the single source for click mapping and drawing. cairo-xlib needs the bounds check in `run()` (XShm events have type > LASTEvent).
- Clicks: volume icon -> `spawnat` -> `rice-volume --at X Y`; avatar -> `rice-power --at X Y`.
- Keys: `Alt+arrows` snap half/quarter (undo both axes = back to tiling), `Alt+Shift+arrows` move 48px, `Alt+Ctrl+arrows` resize, `Mod+Shift+g` canvas mode (floating + drag the background or `Mod+Shift`+drag to pan all windows; accent arrows icon in bar), `Mod+Shift+l` lock, `Mod+Shift+r` screen recorder.
- IPC: `xprop -root -f _RICE_CMD 32c -set _RICE_CMD "N, ..."`. `1, X, Y` = view the first empty tag on the monitor at X,Y in tile layout. `2, px` = window gap, `3, px` = gap above bar, `4, px` = bar side gap (all 0-80, arrange runs at once). `5, 0` = reload `~/.config/rice/binds.conf`.
- New scripts in `~/.local/bin`: `rice-power` (account card), `rice-session` (lock/logout/reboot/poweroff/restore; logout snapshots apps to `~/.cache/rice/session.json`, closes windows, `loginctl terminate-session`), `rice-lock` (own X11 locker, `unix_chkpwd`, blurred desktop, MPRIS card, via `lib/rice/mpris.py`), `rice-record` (ffmpeg x11grab, libx264, `~/Videos`), `rice-scene` (rice mode scene), `rice-setup-root` (run once with sudo: SDDM link dir `/var/lib/rice-sddm`, sudoers for runit-init).
- `rice-volume` v2: critically damped spring on the GTK frame clock, 1:1 while dragging, one wpctl call in flight (latest wins). Click mode has Output/Input pickers (pactl) and a record-and-play-back mic test; `--osd` is centred on screen.
- `rice-shot`: 8 resize handles on the selection, fullscreen toolbar button, `f` (desktop) and `m` (monitor) keys.
- Theme hooks (`lib/rice/hooks.py`, called from `themes.apply`): fastfetch (`config.jsonc` derived from `config.jsonc.tmpl`, plus `rice.jsonc` with ASCII logo), btop (`themes/rice.theme`, USR2 reload), cava (RICE-THEME block, USR1 reload), konsole `rice` profile + colorscheme, SDDM (only on final apply, needs `rice-setup-root`). `r` in theme-switch toggles rice mode (`~/.cache/rice/ricemode`): Enter then runs `rice-scene`.
- Corner glitches came from radius mismatch: picom rounds `RiceCard` and `Rofi` at 26, so every card and rofi theme must use 26. `RiceLock` is excluded from rounding/blur.
- Hung-shell warning: `pkill -f` killed the calling shell again; use PIDs.

## Session 6b: the real cause of choppy animation (2026-11-17)

- NVIDIA syncs OpenGL swaps to ONE display. With DP-4 (165 Hz) and HDMI-0 (75 Hz) the default is HDMI-0, so picom presented every frame at 75 Hz and everything on the 165 Hz monitor stepped in 13 ms. Measured with a bare GLX swap test (ctypes, `glXSwapIntervalEXT(1)`, in the session scratchpad): 75 swaps/s by default, 165 with `__GL_SYNC_DISPLAY_DEVICE=DP-4`, 75 with `DP-0`.
- Fix: `~/.xprofile` now starts picom as `__GL_SYNC_DISPLAY_DEVICE=DP-4 picom --config ...` (backup `~/.xprofile.pre-glsync`). It takes effect only after picom is restarted (re-login, or kill the real picom and start it with that variable). Claude was not allowed to restart picom: the user must do it.
- HDMI-0 (75 Hz) will then show frames unsynced (possible tearing there). If that matters, swap the variable to `DP-0`/HDMI and accept 75 Hz everywhere.
